# Template updates

`justpen-browser-mcp` adopted the shared development framework from
[`justpen-mcp-dev-template`](https://github.com/justpenkit/justpen-mcp-dev-template)
through a reviewed migration from the v0.3.1 template reference. Its browser
implementation, 43 tools, product documentation and existing application release
history remain application-owned.

## Enrollment and history

The migration renders a fresh reference with the real project answers and
compares it against this existing server. Its Copier record describes that
reference; it does not claim that the server was originally generated by Copier.
The reference's initial-version answer is a template baseline, not the current
application version. Run `make version` to read the current server version.

Keep `.copier-answers.yml` committed after enrollment. Let Copier maintain its
source, revision and answers; never fabricate earlier answers to make an update
appear automatic. Preserve the actual Git history and the explicit changelog
boundary, including the application's v0.1.0 through v0.4.0 releases. Do not run
a first-run template bootstrap on this established project.

## Update on a feature branch

Begin with a clean, committed checkout. Fetch an exact upstream reference without
bringing template release tags into the application's tag namespace:

```bash
git switch -c chore/update-template
git fetch --no-tags https://github.com/justpenkit/justpen-mcp-dev-template.git main:refs/remotes/template/main
template_commit=$(git rev-parse refs/remotes/template/main)
uvx --from 'copier>=9.18.2,<10' copier update --vcs-ref="$template_commit" --defaults
git diff
```

Codex uses `codex/update-template` as its feature branch. The commands above use
the source recorded during enrollment and the fetched commit as the update
revision. Use a full clone and fetch before every update, including on another
computer. Never merge the template branch into the application or copy its tags.

`--defaults` reuses recorded answers. Keep the recorded initial-version answer:
Copier compares generated baselines while preserving the application's own version
changes. Omit `--defaults` to review answers again. Use
`--vcs-ref=:current:` when changing answers without upgrading the template.
Always specify a revision rather than relying on a repository's default tags.

## Review the merge

Copier merges the old reference, the new reference and application changes.
Changes on the same lines can produce conflicts. Inspect `git status` and every
diff, resolve all conflict markers, and preserve:

- The `justpen_browser_mcp` package and browser tool registrations.
- Camoufox setup, Playwright compatibility bounds and separate end-to-end tests.
- The product guides, tool references, URLs, anchors and branding.
- The actual application version, historical release notes and changelog boundary.
- Local permission policy and the project's formatting, lint and typing gates.

Then run, separately, from the project root:

```bash
uv lock
make setup
make check
make docs-build
```

Run `make test-e2e` when the update affects browser behavior. Review and commit
through a PR, merge with a regular merge commit, and do not bump the application
version merely because the framework changed. Do not use `copier recopy` as an
update shortcut: it can overwrite application changes.

## When a coding agent performs the update

Before applying direct root `pyproject.toml` or `uv.lock` changes, render the same
update in a disposable checkout, present the exact diff and obtain approval for
that concrete change. Existing approval covers the agreed change; ordinary
uv-managed dependency resolution follows the shared policy. Never bypass the
metadata gate with an indirect writer. See the [agent guide](../contributing/agents.md).

For other established projects without a Copier record, generate a separate
reference and migrate deliberately in a reviewed PR. Do not invent an answers
file or run bootstrap. See [Copier's update documentation](https://copier.readthedocs.io/en/stable/updating/)
for the merge model and recovery options.
